# حذف الحساب في سند

## التدفق

1. المستخدم يفتح **الحساب → حذف الحساب**.
2. تظهر له آثار الطلب وسياسة الاحتفاظ بشكل واضح.
3. بعد تأكيد ثانٍ، يستدعي التطبيق Edge Function باسم `request-account-deletion`.
4. الوظيفة تتحقق من جلسة المستخدم ولا تقبل user_id من العميل.
5. إذا كان هناك طلب فعال، تعيد الطلب نفسه بدل إنشاء نسخة مكررة.
6. إذا لم يوجد، تنشئ `account_deletion_requests` بحالة `requested`.
7. Push devices للحساب تُعطل عند بدء الطلب.
8. المستخدم يقدر يتابع الحالة أو يلغي الطلب قبل اكتماله.

## لماذا لا نحذف Auth مباشرة؟

قاعدة سند تحتوي سجلات عقارية ورسائل ومواعيد ومكاتب ومعاملات وتدقيق مرتبطة بالحساب. بعض العلاقات مصممة لمنع الحذف الصامت حتى لا ينكسر سجل المعاملة. لذلك الحذف النهائي يحتاج سياسة واضحة لكل نوع سجل: حذف، إخفاء هوية، أو احتفاظ مبرر.

## الأمان

- العميل يملك SELECT فقط على طلبه عبر RLS.
- INSERT/UPDATE/DELETE من العميل ممنوعة.
- الكتابة تمر عبر Edge Function موثقة بجلسة المستخدم.
- service-role يبقى داخل Supabase فقط.
- الحذف النهائي لحساب Auth لا ينفذ من تطبيق المستخدم.

## التشغيل قبل الإطلاق العام

- اعتماد مدة معالجة طلبات الحذف.
- تحديد قواعد الإخفاء/الاحتفاظ لكل جدول مرتبط بالمستخدم.
- بناء مسار مراجعة إداري للحالات `under_review` و`blocked`.
- اختبار طلب/إلغاء/اكتمال الحذف بحسابات اختبار.
- نشر Privacy Policy نهائية ورابط دعم HTTPS.
