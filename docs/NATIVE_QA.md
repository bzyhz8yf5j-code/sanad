# سند — خطة QA للآيفون

هذه الخطة مخصصة لأول Development Build على iPhone، وتُنفذ من شاشة **الحساب → فحص الجهاز والاتصال** ثم عبر المسارات الأساسية.

## 1) فحص البيئة

- EAS Project ID يظهر بحالة سليمة.
- Supabase health يظهر متصلًا.
- Map Style: يسمح بالتجريبي في development فقط، ويجب أن يكون مرخّصًا قبل production.
- Push permission يُقرأ بدون طلب الإذن تلقائيًا.
- طابور Offline يعرض العمليات المحلية والملاحظات الميدانية.

## 2) الحساب

- إنشاء حساب.
- تسجيل الدخول والخروج.
- استرجاع الجلسة بعد إغلاق التطبيق وإعادة فتحه.
- التأكد أن المستخدم العادي لا يحصل على صلاحيات مكتب/إدارة.

## 3) العقارات

- البحث وفتح التفاصيل.
- المفضلة.
- مكتب معتمد: إنشاء Draft، تعديل البيانات، رفع الصور، تحديد الغلاف، فحص المخاطر، النشر.
- التأكد أن العقار غير الجاهز لا يُنشر.

## 4) الخرائط والميدان

- فتح مركز سند الجغرافي.
- منح Location permission.
- بدء جلسة ميدانية.
- تسجيل GPS.
- التقاط صورة.
- حفظ ملاحظة.
- اختبار Offline ثم إعادة الاتصال والمزامنة.
- التأكد أن الصورة المحلية تُحذف بعد نجاح الرفع.

## 5) الإشعارات

- الضغط على «فحص وتفعيل Push».
- التأكد من تسجيل Expo Push Token للحساب.
- اختبار Deep Link من إشعار إلى العقار/المعاملة عند توفر Push worker.

## 6) الجودة

- العربية RTL.
- أحجام النصوص على iPhone صغير وكبير.
- VoiceOver للعناصر الرئيسية.
- تقليل الحركة.
- عدم ظهور بيانات Demo كبيانات رسمية.
- عدم استخدام demo map tiles في production.

## نتيجة الاختبار

يسجل لكل بند: PASS / FAIL / BLOCKED مع نسخة التطبيق، نوع الجهاز، إصدار iOS ووقت الاختبار.
