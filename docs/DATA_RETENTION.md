# سياسة الاحتفاظ بالبيانات — مسودة تقنية

هذه مسودة تقنية تحتاج اعتمادًا قانونيًا وتشغيليًا قبل الإنتاج.

## طلب حذف الحساب

- المستخدم يقدر يبدأ طلب حذف الحساب من داخل التطبيق.
- الطلب يُخزن في `account_deletion_requests` ولا ينفذ حذفًا عشوائيًا فورًا.
- عند الطلب تُعطل أجهزة Push الخاصة بالحساب.
- يقدر المستخدم إلغاء الطلب قبل اكتماله؛ عند الإلغاء يمكن للتطبيق إعادة تسجيل Push إذا الإذن ما زال ممنوحًا.
- البيانات الشخصية القابلة للحذف تُعالج ضمن مسار الحذف.
- السجلات المرتبطة بمعاملة قائمة، سجل تدقيق، نزاع أو التزام حفظ تحتاج مراجعة احتفاظ/إخفاء هوية قبل حذف الحساب النهائي.

## مدد تشغيلية تحتاج اعتمادًا

- Audit events: احتفاظ افتراضي مقترح 24 شهرًا، ثم أرشفة/حذف عبر backend فقط.
- تقارير PDF: روابط العرض موقعة وقصيرة العمر؛ الملف الأصلي الخاص يخضع لسياسة احتفاظ المشروع.
- ملفات العقار والمعاملات: لا تُحذف تلقائيًا طالما توجد معاملة قانونية/نزاع/التزام حفظ.
- Push tokens: يعطل الرمز عند فشل دائم أو تسجيل خروج أو بدء طلب حذف.
- الصور والوسائط: الحذف المنطقي للإعلان لا يعني بالضرورة الحذف الفوري إذا كان مرتبطًا بمعاملة أو سجل تدقيق.
- النسخ الاحتياطية: يجب تحديد RPO/RTO قبل الإطلاق وربط اختبارات استعادة دورية.

لا تعتبر هذه المدد سياسة قانونية نهائية إلى أن تعتمد رسميًا.
